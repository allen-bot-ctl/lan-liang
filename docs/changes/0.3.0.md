# 栏量 LanLiang v0.3.0 契约（mind，2026-11-25 02:31 NY，口径以老板补充 + PM 02:29 NY 四点定稿为准）

三件事，其余同 0.2.2：
1. 监听服务：Codex、Gemini 可以分别开关；开着的才显示，至少保留一个。
2. 只开一个服务时，菜单栏和面板都换成放大的「仅一个」状态。
3. 消耗汇总：一个累计合计数，下面列出各家的累计。

以上三项都放进新的设置窗口（520 宽，三张卡片）。

样稿：`practice` 产出的 `lanliang-0.3.0-settings.html` 和截图 `ll-030-*.png`，已推到 `docs/design/0.3.0/`（fbc3514）。样稿是 demo，不进产品代码。设计数值沿用 `docs/changes/0.2.0.md` 第 2 节，本契约只写新增和改动的部分。

## 限制（同 0.2.0，原样执行）
- 最低 macOS 13，不能用 14 以上的新接口。
- 不用 Swift Charts（Intel CI 机器上会崩）。
- 文案和变量名都不能出现 sessions 和 .jsonl。
- 半透明效果以老板 Mac 实机为准，CI 截图只作参考。

## 不变
- 数据源、取数方式、刷新节奏、缓存、数字格式（`Fmt.tokens`、刻度规则）、现有状态文案都不变。
- 不新增任何数据请求。消耗汇总只用面板已经拿到的数据相加。
- 不加新图表类型。

## 1. 监听服务
- 新增偏好 `UserDefaults`：`monitor.codex`、`monitor.gemini`，类型 Bool，默认都为 true。升级用户保持两个都开。
- 关掉的服务：
  - 菜单栏不显示它那一行；
  - 面板不显示它的页签和内容；
  - 停止请求它的额度和用量（Codex 不调 wham，Gemini 不调 Cloud Code，也不做本机扫描）；
  - 已有的缓存文件保留，不删。
  - 重新打开时立即刷新一次。
- **至少保留一个**：只剩一个开着时，它的开关置灰（disabled），不能关。下面显示一行提示「至少保留一个服务，最后一个开关不能关。」
- 「开着但没登录」和现在一样：菜单栏回退到栏量图标的规则不变，面板显示「未检测到登录」。

## 2. 「仅一个」状态（只开一个服务时）
- 菜单栏：用单行大字。图标 15pt，周剩余 14pt 半粗，5 小时剩余 11pt、55% 透明，等宽数字。比现有单行样式（12/10pt）大一档；宽度仍然按最长文案「100%」「100」固定。两个服务都开时，保持现在的上下两行不变。
  - 现有代码在「只登录一个」时已经能单行显示（`MenuBarLayout.single`）。本版改成按「开着的服务数」选样式：只开一个时用新的放大样式；两个都开但只登录一个时，沿用现有单行样式。
- 面板：去掉页签条，换成「服务头」卡片（叠色底，圆角 10）：服务图标 16pt（放在 28×28 的圆角底上）+ 名称 15pt 半粗 + 套餐徽章 + 掩码邮箱；Codex 靠右再加「剩 N 天」。
  - 下面的剩余额度卡放大：百分比 28pt 半粗（新增的字号，只用在「仅一个」状态和消耗汇总的总数上），进度条 6pt，行间 14。
  - 用量卡不变。
- 两个服务都开：和 0.2.2 完全一样。

## 3. 设置窗口（替换 0.2.0 第 7 节）
- 宽 520，固定尺寸，不能缩放，只开一个。窗口高度跟内容走：两个都开约 470；只开一个时多出提示行。内边距 16，卡片间距 12。
- 从上到下三张卡片（圆角 10，卡片底和描边沿用 0.2.0），最下面一行信息：
  1. **监听服务**：标题 13pt 半粗 + 说明 10pt「开启的服务显示在菜单栏和面板里；只开一个时放大显示」。
     - 每个服务一行，行高 48：28×28 叠色底上放服务图标，名称 13pt，下面一行 10pt「已登录 · 套餐 · 掩码邮箱」或「未检测到登录」，靠右是开关。
  2. **消耗汇总**：标题 + 说明「Codex + Gemini 累计」（只开一个时写「仅已开启的服务」）。见第 4 节。
  3. **通用**（原来的两个开关）：登录时启动、自动检查更新，行为同 0.2.0。
  - 信息行：图标、「栏量 0.3.0」、有新版本时显示「x.y.z 可用」、检查更新、退出栏量，同 0.2.0。
- 开关都用橙色强调色；置灰的开关透明度 45%，鼠标是禁止手型。

## 4. 消耗汇总口径（老板定、PM 02:26 NY 定稿）
- **累计 = 面板柱状图里 Codex 已有数据的全部日合计 + Gemini 已有数据的全部日合计。**
  - Codex：`model.official` 里所有日期的值相加，也就是官方接口返回的全部天数。天数由服务端决定，不补、不估。
  - Gemini：`geminiHistory.daily` 里所有日期的值相加，也就是本机 Antigravity 的全部记录，含磁盘缓存。
- 只放一个大数，不分「本月」，不写起始日期。
- 累计只放在设置窗口，面板不加累计数字（PM 02:29 NY 定）。
- 只开一个服务时，只显示它自己的累计，不画占比条，不写百分比。
- 显示：
  - 第一行：「累计」12pt 次要色 + 总数 28pt 半粗（`Fmt.tokens`，例如「197.69亿」）+「Tokens」13pt 次要色。
  - 两个都开时，下面画 8pt 占比条：Codex 用橙色渐变，Gemini 用 #8E8CF5，中间留 2pt 缝。
  - 再下面是图例行：色块 + 「Codex 193.00亿 97.6%」、「Gemini 4.69亿 2.4%」。百分比保留一位小数，数字半粗、等宽。
- **Codex 接口失败（`official == nil` 且已加载）**：
  - 总数只算 Gemini；
  - 「累计」后面加小标「不完整」：10pt 半粗，橙字，橙色 14% 底，圆角 5；
  - Codex 那一项显示「—」和「官方用量暂时拿不到」；
  - 不画占比条，不写百分比。
  - 加载中（还没拿到）显示「正在统计…」，不显示 0。
  - Gemini 全部读取失败时同理，标「不完整」。
- 窗口开着时数据更新了，就跟着刷新。

## 验收
1. 单测：
   - 偏好读写和默认值（两个都开）；
   - 「至少一个」规则：只剩一个时关不掉，偏好不变；
   - 累计计算：两个服务、只开一个、Codex 失败（只算 Gemini、带不完整标记）、加载中；
   - 格式：19_300_000_000 + 469_000_000 →「197.69亿」，占比「97.6% / 2.4%」；
   - 关掉的服务不发请求（计数器断言）。
2. CI 截图，亮暗各一张：
   - 设置窗口：两个都开、只开 Codex（Codex 开关置灰加提示）、Codex 失败「不完整」；
   - 菜单栏：双服务、只开 Codex、只开 Gemini；
   - 面板：只开 Codex、只开 Gemini，悬停一根柱子。
3. 最长文案不截断：「Google AI Ultra」、长邮箱（尾部省略）、「已登录 · Google AI Ultra · a***@verylongcompanydomain.com」、「至少保留一个服务，最后一个开关不能关。」、总数「9999.99亿」。
4. 老板 Mac 实机走查：
   - 来回开关服务，菜单栏和面板即时切换；
   - 最后一个开关置灰；
   - 重启后保持选择；
   - 累计数和面板各家柱状图全部合计一致；
   - 断网时出现「不完整」。
5. 无回归：两个都开时菜单栏、面板和 0.2.2 一致；0.2.2 的单测和截图全绿；右键菜单三项还在；额度先出仍然满足。
6. Codex 接口失败时，设置窗口的消耗汇总显示「不完整」小标，总数只含 Gemini（单测加截图）。
