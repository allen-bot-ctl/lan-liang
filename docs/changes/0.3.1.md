# 栏量 LanLiang v0.3.1 契约（mind，2026-11-25 03:5x NY，PM 03:47 NY 定方案 A：堆叠柱）

只改一件事：设置窗口的「消耗汇总」卡，从「一个大数 + 占比条」换成和面板一模一样的 Token 用量柱状图，把开着的服务叠在一起画。其余同 0.3.0。

背景：老板反馈 0.3.0 只给了一个「198 亿」的合计，看不出每天、每家用了多少。要求用外面一模一样的柱状图，只是把几家的数据合并起来画。

## 限制（同 0.2.0 / 0.3.0）
- 最低 macOS 13，不能用 14 以上的新接口。
- 不用 Swift Charts（Intel CI 机器上会崩），继续自己画。
- 文案和变量名都不能出现 sessions 和 .jsonl。
- 半透明效果以老板 Mac 实机为准，CI 截图只作参考。

## 1. 卡片结构
- 卡片标题「消耗汇总」和说明保持 0.3.0 的写法。
- 标题下第一行是累计合计，保留但小一号，和面板「Token 用量」标题行同一种排法：左边「累计」12pt 次要色，后面「197.69亿」13pt 半粗、等宽数字，「不完整」小标照旧，最右边是 每日 / 每周 / 每月 分段（复用面板的分段组件）。
- 下面是柱状图，**直接复用面板的柱状图组件**：
  - 高 132，坐标轴、刻度规则、刻度列宽量法、网格（中线虚线、底线）、日期标签和面板一样；
  - 每日 30 天、每周 12 周、每月 6 个月，和面板一样；
  - 悬停时其余柱子降透明、加竖线，规则也和面板一样。
- 去掉 0.3.0 的占比条和图例行。
- 分段的选择只在设置窗口里生效，不影响面板的选择；默认每日。

## 2. 堆叠柱
- 两个服务都开时，每根柱子分上下两段：Codex 在下（橙色渐变 `Theme.codexFill`），Gemini 在上（#8E8CF5，`Theme.geminiFill`）。
  - 两段之间不留缝；只有最上面那段的柱顶是 2pt 圆角。
  - 某一家当天是 0 时，只画另一段。
- 纵轴最大值按**每根柱子的合计**取最大，刻度用面板同一套规则（「4450万」「3.35亿」等）。
- 只开一个服务时就是普通单色柱：Codex 橙，Gemini 也用面板现在的橙色。这时和面板那家的图完全一致。
- **悬停气泡**（反色，和面板同样式）：
  - 第一行：日期（或区间）；
  - 中间两行：色块 + 「Codex 2.86亿」、色块 + 「Gemini 6600万」，数字用 `Fmt.tokens`；
  - 最后一行：「合计 3.52亿 Tokens」半粗。
  - 只开一个服务时，保持面板的两行气泡。
  - 气泡不能超出图区。
- 数据：Codex 用 `model.official`，Gemini 用 `geminiHistory.daily`，按 `TokenSeries.bars` 同样的时间段分别求和后叠起来。不新增请求。

## 3. 「不完整」与状态（规则同 0.3.0）
- Codex 接口失败：合计只算 Gemini，「累计」行带「不完整」；图里只画 Gemini 那一段（保持 #8E8CF5，提示这是部分数据），气泡用两行。
- Gemini 全部读取失败同理。
- 两家都没拿到时，图区显示「正在统计…」或「官方用量暂时拿不到」，复用面板的状态视图。

## 4. 窗口尺寸
- 宽 520 不变。高度跟内容走：两个都开时约 470 → 约 580（消耗汇总卡增加分段行和 132 高的图，减去原来的占比条和图例行），只开一个时再加提示行。
- 尺寸都在 0.2.0 视觉规范内：不加新字号，圆角、间距、颜色沿用。

## 验收
1. 单测：
   - 堆叠两段之和等于当天合计（每日、每周、每月各测一组）；
   - 一家为 0 时只有一段；
   - 纵轴最大值等于各柱合计的最大值；
   - 只开一个服务时，数据和面板那家完全一致；
   - Codex 失败时合计只含 Gemini，并带「不完整」。
2. 最长刻度标签不截断：合计最大值为 9_999_000_000（「99.99亿」）以及「8900万」时，刻度列宽按最宽文字量出，不缩小。
3. 悬停气泡四行完整、不超出图区：分别悬停最左和最右的柱子。
4. CI 截图，亮暗各一张：两个都开的每日加悬停气泡、每月；只开 Codex；Codex 失败显示「不完整」。
5. 老板 Mac 实机走查：设置窗口的图和面板两家的图逐日对得上；切换 每日 / 每周 / 每月 正常。
6. 无回归：面板、菜单栏、监听服务、通用开关和 0.3.0 一致；0.3.0 的单测和截图全绿。
