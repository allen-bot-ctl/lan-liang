# 栏量 0.4.0 契约：AI 会话状态（第一版）

需求：老板 2026-11-27（「竞品还能知道它们各自的状态，工作中、空闲中、询问对话等等」）。范围以 PM 2026-11-27 群内「栏量 AI 状态第一版」四条决定为准。基线 master a6c9a4e（最新 tag v0.3.15）。样稿：`docs/changes/assets/0.4.0-status.html`（只是样稿，不进产品代码）。

## 背景
- 竞品调研见 mind 研究文档 `agent-status-research.md`。结论：不装 hooks、只读本机日志，能可靠分出「工作中 / 完成 / 中断」；「等你确认」只读日志分不出。
- coder 在老板 Mac 上只读统计了事件名，没读内容：
  - Codex `~/.codex/sessions/**/rollout-*.jsonl`：`task_started`、`task_complete`、`turn_aborted` 都有。
  - Antigravity `~/.gemini/antigravity/brain/*/transcript.jsonl`：有 status 字段，取值 RUNNING / DONE / ERROR / USER_INPUT。
- 0.1.5 §5 删掉 Codex 本机日志扫描，是因为 `~/.codex/sessions` 有 2.7GB，全量扫描让启动等了约 90 秒。本版重新读这个目录，但只读状态事件，不扫历史（见 §1）。

## PM 决定（原样落实，不加不减）
1. 判断方式：FSEvents 文件监听，零配置读日志，只读事件类型，不读对话正文，不要任何系统权限。批准改写 0.1.5 §5「不再读 sessions」，新条文限定为「只读状态事件」。hooks 开关放到第二版。Antigravity 的「工具执行前」钩子永远不注册，language server 的令牌也不读。
2. 状态：Codex 显示工作中、刚完成、已中断；Antigravity 显示工作中、刚完成、出错。「等你确认」「问用户问题」第一版都不显示。日志里不认识的事件一律忽略，不报错。
3. 展示：菜单栏额度旁的小点，加面板里的「会话」一栏。第一版不发系统通知。
4. 必须做到：工作中超过 N 分钟没有新事件就自动退回空闲，N 写进合同；守住空闲 CPU 红线；日志格式变了也不能崩。

## 1. 读什么、怎么读

### 1.1 Codex
- 目录：`$CODEX_HOME/sessions`，没有 `CODEX_HOME` 时用 `~/.codex/sessions`。只认文件名 `rollout-*.jsonl`。
- 一个 rollout 文件 = 一个会话。
- 每行是一个 JSON 对象。只认 `type == "event_msg"` 的行，只取 `payload.type` 和 `timestamp`，其余字段不取、不存、不进日志：

| `payload.type` | 会话状态 |
|---|---|
| `task_started` | 工作中 |
| `task_complete` | 刚完成 |
| `turn_aborted` | 已中断 |
| 其他任何值（含 `request_user_input` 相关、`token_count`、`error` 等） | 忽略，状态不变 |

### 1.2 Antigravity
- 目录：`~/.gemini/antigravity/brain/`。只认这个目录下任意深度、文件名正好是 `transcript.jsonl` 的文件（兼容 `brain/<id>/transcript.jsonl` 和 `brain/<id>/.system_generated/logs/transcript.jsonl` 两种位置）。一个文件 = 一个会话。
- 每行是一个 JSON 对象。只取顶层 `status` 字段（字符串），其他字段（含 type、source、正文）一律不取、不存、不进日志：

| `status` | 会话状态 |
|---|---|
| `RUNNING` | 工作中 |
| `DONE` | 刚完成（去抖：DONE 之后 5 秒内同一文件又出现 RUNNING，就不切到刚完成，保持工作中） |
| `ERROR` | 出错 |
| `USER_INPUT`、其他任何值、没有 status | 忽略，状态不变 |

- 去抖的理由：DONE 可能是每一步的状态，不一定是整轮结束。老板 Mac 实测（验收 C4）如果发现一轮任务中间就会闪绿点，coder 在群里报，由 PM 决定是否改映射。
- 只读这个文件。不注册任何 hooks（包括「工具执行前」钩子，永远不注册），不改 `~/.gemini/config/*`，不连 language server 取状态，不读 language server 的令牌。

### 1.3 读取方式（两边相同）
- **监听**：用 FSEvents（`FSEventStreamCreate`，延迟 1 秒，带 `kFSEventStreamCreateFlagFileEvents`）分别监听上面两个目录，回调放在后台队列，主线程只接收归并后的状态。不轮询，不开计时器扫描目录。
- **启动时不扫历史**：
  - Codex 只列今天、昨天两个日期目录（`sessions/YYYY/MM/DD`），不递归枚举整个 `sessions`。
  - Antigravity 只列 `brain/` 下一级子目录，取 mtime 在 10 分钟内的子目录，再找其中的 transcript.jsonl。
  - 只处理 mtime 在 10 分钟内的会话文件；每个文件只读末尾 64KB，找最后一条认识的事件。
  - 启动时只恢复「工作中」：最后一条认识的事件是工作中、且文件 mtime 在 10 分钟内，就显示工作中，起始时间取那条事件的时间；其余情况一律当空闲，启动前发生的完成、中断、出错不补显示。
  - 会话状态的读取在后台进行，不阻塞额度显示（0.1.5 §5 额度先出不变）。
- **增量读**：每个会话文件记一个字节偏移。收到这个文件的变化后，只从偏移读到文件末尾，按 `\n` 切行。最后一段没有换行的半行不解析，偏移停在最后一个换行之后，等下次补齐再读。
- **上限**：
  - 一次最多读 1MB，超出部分下次接着读。
  - 单行超过 64KB 直接跳过，不做 JSON 解析（状态行都很短，长行是正文）。
  - 只对含 `"event_msg"`（Codex）或 `"status"`（Antigravity）字样的行做 JSON 解析。
- **轮换与异常**：
  - 文件变小（被截断或替换）：偏移归零，按新文件处理，只读末尾 64KB。
  - 文件被删除：这个会话移除。
  - 新出现的文件：从头读，超过 64KB 时只读末尾 64KB。
  - 目录不存在：这个工具显示空闲。随现有额度刷新顺带看一次目录有没有出现，出现后再开始监听，不另加轮询。
- **容错**：坏 JSON、字段缺失、字段类型不对、编码错误、读失败，都只跳过这一行或这一次，不弹窗、不写错误提示、不影响额度。整个监听模块出任何错，只会让「会话」显示空闲，不能让应用崩溃。
- **不读正文**：
  - 不保存、不打印、不上传任何行内容。日志里只能出现事件名、状态名、时间、会话个数，不能出现文件路径里的会话 id。
  - 不写磁盘缓存，状态只在内存里。
  - 不写 `~/.codex/*`、`~/.gemini/*`。

### 1.4 超时、淡出
- **N = 10 分钟**：某个会话在工作中，10 分钟内它的文件没有追加任何新行（任何新行都算，不必是认识的事件），就退回空闲。
  - 理由：Codex 工作时每次模型回复、每次工具调用都会写行（如 `token_count`），10 分钟一行都没写，基本可以认定会话已经停了（终端被关、进程被杀）。
  - 一次很长的单个命令（如长编译）期间也不写行，10 分钟能盖住绝大多数这种情况；比这更短容易误退回空闲，更长则卡住的蓝点要挂太久。
- **刚完成**：显示 60 秒后自动变成空闲。
- **已中断、出错**：同样显示 60 秒后变空闲，与刚完成一致。
- 期间同一会话来了新事件，就按新事件切换状态，重新计时。
- 计时用一次性定时器：到点只触发一次，算出下一个到点时间再排下一次。不用周期性计时器，没有到点事件时不唤醒。

### 1.5 归并
- 同一工具有多个会话时，按优先级取一个作为这个工具的状态：工作中 > 已中断（Codex）/ 出错（Antigravity）> 刚完成 > 空闲。工作中的时长从这些会话里最早开始的那个算起。
- 菜单栏小点：两个工具的状态再按同样优先级取一个。
- 跟随设置里「监听服务」：关掉的服务不监听、不显示（Codex 关掉 → 不监听 Codex 会话；Gemini 关掉 → 不监听 Antigravity 会话）。不新增设置项。

## 2. 菜单栏小点
- 位置：额度文字块的右侧，一个点。两行模式、单行模式都垂直居中于整个状态项。
- 大小：直径 6pt，左边距 4pt。有点时状态项变宽 10pt；空闲时不画点、不占位，宽度和 0.3.15 一样。宽度只在点出现和消失时各变一次。
- 颜色（菜单栏浅色 / 深色），使用系统色的固定值：

| 状态 | 颜色 | 浅色 | 深色 | 动效 |
|---|---|---|---|---|
| 工作中 | 蓝 | `#007AFF` | `#0A84FF` | 慢闪：每 1 秒在 100% 和 35% 不透明度之间切换一次（周期 2 秒），两帧硬切，不做渐变 |
| 刚完成 | 绿 | `#34C759` | `#30D158` | 常亮 60 秒后消失 |
| 已中断 / 出错 | 红 | `#FF3B30` | `#FF453A` | 常亮 60 秒后消失 |
| 空闲 | 不显示 | — | — | — |

- 系统「减少动态效果」打开时，工作中的蓝点常亮不闪。
- 慢闪实现：两帧位图在状态进入工作中时预先渲染一次（沿用 0.3.13 的位图缓存），之后只换图，不重新排版、不改宽度。额度数字或外观变化时，两帧一起重渲染。

## 3. 面板「会话」一栏
- 位置：在两个页签里都放在额度区（`ServiceSection`）上面，是滚动内容的第一栏，内容在两个页签一样。
- 结构：标题「会话」（12pt semibold，次级色），下面每个开着的工具一行，固定两行顺序 Codex、Antigravity。两个服务都关掉时整栏不显示。卡片样式、圆角、内边距与额度区一致。
- 每行：左边 6pt 圆点（颜色同 §2，空闲时不画点但留位）+ 工具名（13pt，主色）；右边状态文字（12pt，等宽数字，右对齐），行高 22pt。
- 状态文字（唯一写法）：

| 状态 | 文字 | 颜色 |
|---|---|---|
| 工作中，< 1 分钟 | 工作中 | 蓝 |
| 工作中，1–59 分钟 | 工作中 · 12 分钟 | 蓝 |
| 工作中，≥ 60 分钟 | 工作中 · 1 小时以上 | 蓝 |
| 刚完成 | 刚完成 | 绿 |
| 已中断（Codex） | 已中断 | 红 |
| 出错（Antigravity） | 出错 | 红 |
| 空闲 | 空闲 | 三级灰 |

- 最长文案：左「Antigravity」，右「工作中 · 1 小时以上」。面板宽 400pt，减去左右内边距后一行可用约 356pt，工具名列固定 96pt，右侧状态列可用约 250pt，最长文案约 120pt，不截断、不换行。
- 时长随现有顶栏的 30 秒刷新节奏更新，只在面板可见时刷新。
- 不显示会话标题、项目路径、对话内容、会话个数，不可点击。
- 第一版不发系统通知，不加声音。

## 5. 验收

### A. 单测（fixtures 里的假日志，放 `fixtures/agent-status/`，不含任何真实内容）
1. Codex 每个事件：`task_started` → 工作中，`task_complete` → 刚完成，`turn_aborted` → 已中断。
2. Antigravity：RUNNING → 工作中；DONE → 5 秒后刚完成；DONE 后 5 秒内再 RUNNING → 保持工作中；ERROR → 出错；USER_INPUT → 状态不变。
3. 未知事件：未知的 `payload.type`、未知 status、没有 status、`request_user_input_async` 的 function_call 行，状态都不变，不抛错。
4. 坏行：非 JSON、字段类型不对、空行、超过 64KB 的行，都跳过；后面的正常行照常生效。
5. 截断行：最后半行没有换行时不解析；补齐换行后再读，生效一次且只一次。
6. 文件轮换：文件变小后偏移归零重读；文件删除后会话移除；新文件从头读（超 64KB 只读尾部）。
7. 超时：工作中 10 分钟没有新行 → 空闲；第 9 分 59 秒追加任意一行 → 仍是工作中并重新计时。刚完成、已中断、出错 60 秒后 → 空闲。用注入时钟，不真等。
8. 归并：多会话按「工作中 > 已中断/出错 > 刚完成 > 空闲」；菜单栏取两工具中优先级最高者；工作中时长取最早开始的会话。
9. 启动：只列今天、昨天两个日期目录；10 分钟前的文件不打开；每个文件读取不超过 64KB；只恢复工作中。用注入文件系统统计打开次数和读取字节数。
10. 不读正文：fixture 正文里放一个标记串，断言状态模块的内存结构和所有日志输出里都没有它，也没有会话 id。
11. 服务开关：关掉 Codex 后不创建 Codex 监听；关掉 Gemini 后不创建 Antigravity 监听。
12. 0.3.15 及更早的测试全绿。

### C. 老板 Mac 实测（coder 装好 0.4.0 后，按顺序走一遍）
1. 退出栏量再打开：菜单栏额度 ≤ 3 秒出现，Codex、Gemini 两行都有数字（沿用 0.1.5 验收 8）。
2. 在 Codex 里发一个要跑一会儿的任务：1–2 秒内菜单栏额度右侧出现蓝点慢闪，面板「会话」里 Codex 行显示「工作中」。
3. 等它完成：蓝点变绿点，面板显示「刚完成」；约 1 分钟后绿点消失，面板变「空闲」。
4. Antigravity 跑一个任务：出现蓝点，面板 Antigravity 行「工作中」；一轮中途不应闪绿点（如果闪了，记下来在群里报）；完成后绿点 1 分钟消失。
5. Codex 再发一个任务，中途按 Esc 打断：红点出现，面板显示「已中断」，约 1 分钟后消失。
6. Codex 和 Antigravity 同时跑：菜单栏只一个蓝点；其中一个先完成时仍是蓝点，面板里两行各自正确。
7. Codex 发一个任务后直接关掉终端窗口（不让它写完成）：蓝点保持，10 分钟后自动消失，面板变「空闲」。
8. 两个都不动时，活动监视器里栏量的 CPU 和 0.3.15 一样，看 1 分钟没有持续占用。
9. 正在工作时退出栏量再打开：额度仍 ≤ 3 秒出现，蓝点随后恢复。
