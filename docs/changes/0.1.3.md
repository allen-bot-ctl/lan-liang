# 栏量 LanLiang v0.1.3 契约（mind，2026-11-24 21:3x NY，范围以 PM 21:31 NY 为准）

三件事，其余同 0.1.2。

## 1. 升级后菜单栏图标消失（老板 0.1.2 真机）
**原因**：0.1.0/0.1.1 第一个创建的状态项是只显示栏量图标的 fallbackItem，没有设 autosaveName，系统自动命名为 `Item-0`。只要有一家登录，它就被设成隐藏，macOS 把 `NSStatusItem Visible Item-0 = 0` 记进 `com.allen-bot-ctl.lanliang` 的偏好设置。0.1.2 唯一的状态项又是第一个创建的，于是继承了隐藏。
**修法**：
- 状态项 `autosaveName = "lanliang.main"`，创建后显式设 `isVisible = true`。
- 每次启动先删掉旧键 `NSStatusItem Visible Item-0/1/2` 和 `NSStatusItem Preferred Position Item-0/1/2`，再创建状态项。
- 单测或启动自检：先写入 `NSStatusItem Visible Item-0 = 0` 再启动，断言状态项可见。CI 截图里加拍这一种「带旧偏好升级」的场景。

## 2. Gemini 登录不再每次读钥匙串（老板 21:31 NY）
栏量只读不写钥匙串这一条不变；钥匙串里的 Gemini 登录是 Antigravity 存的。
- 新增缓存文件 `~/.lanliang/gemini-token.json`：目录权限 700，文件权限 600。内容格式和 Antigravity 的令牌文件一样，就是 0.1.0 契约 §3.1 那份 JSON。
- 读取顺序：
  1. `~/.gemini/jetski-standalone-oauth-token`
  2. `~/.gemini/antigravity-cli/antigravity-oauth-token`
  3. `~/.lanliang/gemini-token.json`
  4. 钥匙串 `gemini`/`antigravity`
  前两份是 Antigravity 自己的文件，有就用，不写缓存。只有从钥匙串读到时，才写一份缓存。
- 在内存里换到新的 access_token 之后，写回缓存，原子写入、权限 600。不写 `~/.gemini`，也不写钥匙串。
- 缓存里的 refresh_token 换新失败（invalid_grant、400 或 401）时，回去重读一次钥匙串。读到的内容和缓存不同，就覆盖缓存再试一次；还是失败，就显示「Gemini 登录已过期，打开一次 Antigravity 后再刷新」。本次运行不再反复读钥匙串。
- 钥匙串被拒，照 0.1.0 §5 的状态表处理。
- 令牌不进日志，也不进 CI 产物。
- 第一次运行 0.1.3 时会从钥匙串读一次，老板之前点过「始终允许」，所以不会弹框，读完写入缓存；从这以后就不再碰钥匙串。

## 3. 两行布局 5 小时数字基线对齐（backlog，PM 21:26 NY 定为下一版）
5 小时小号数字和同一行的周剩余对齐到同一条文字基线。

## 验收
1. 预置 `NSStatusItem Visible Item-0 = 0` 后，从 0.1.2 应用内升级到 0.1.3，菜单栏出现栏量，而且只有 1 个状态项。
2. 只有钥匙串里有 Gemini 登录时，第一次启动会生成 `~/.lanliang/gemini-token.json`，权限是 600。删掉钥匙串项或拒绝授权后重启，仍能正常显示 Gemini 额度。
3. 缓存里的 access_token 过期后自动换新，并写回缓存。整个过程中不弹钥匙串框。
4. 把缓存里的 refresh_token 改坏后，会回钥匙串重读一次并恢复；钥匙串里也没有时，显示登录过期的文案。
5. 放大截图检查：5 小时数字和周剩余同一基线，浅色和深色各一张。
6. 以上单测全绿，CI 截图浅色、深色各一套。
