# 栏量 LanLiang v0.2.0 契约（mind，2026-11-25 00:1x NY，范围以 PM 定稿为准）

这一版只换界面，数据和功能不动：
1. 面板换皮，参照 Quosparr 和栏历的视觉，亮暗两套；
2. 顶栏加三个入口：刷新、升级、设置；
3. 新增独立设置小窗口，只有两项。

样稿（唯一视觉参照）：`docs/design/0.2.0/lanliang-0.2.0-ui.html`，截图有 `ll-ui-v2-light.png`、`ll-ui-v2-dark.png`、`ll-ui-v2-interaction.png`，对比图是 `ll-ui-compare.png`。样稿是 demo，不进产品代码；用 SwiftUI 重新实现。
数值以本契约为准，样稿和本契约冲突时按本契约。

## 不变的部分
- 数据源、口径、刷新节奏（5 分钟定时）、缓存、额度和用量的数字格式、刻度规则（「4450万」等）、所有现有状态文案，都与 0.1.5 相同。
- 不加新图表类型：热力图、折线图、图表样式菜单都不放这版。
- 右键菜单（检查更新… / 登录时启动 / 退出栏量）这版原样保留。

## 限制（coder 读代码结论第 4 条，原样执行）
- 最低 macOS 13，不能用 14 以上的新接口，比如 symbolEffect、ContentUnavailableView、@Observable、SettingsLink、Settings scene。确实要用时，必须用 `#available` 包住，并提供 13 的写法。
- 不用 Swift Charts，因为它在 Intel CI 机器上会崩（无 GPU，触发 Metal 断言）。柱状图继续自己画。
- 文案和变量名都不能出现 sessions 和 .jsonl（CI 有 grep）。
- 半透明效果以老板 Mac 实机为准，CI 截图只作参考。CI 机器上材质发灰时，`--debug` 截图模式可以用不透明兜底底色。

## 2. 设计数值（亮 / 暗）
- 面板宽 400pt（现在是 360），高度跟内容走（现有 fitPanel）。内边距 12，卡片内边距 12，卡片之间 8，行间 12，8pt 网格。
- 窗口：FloatingPanel `backgroundColor = .clear`、`isOpaque = false`；内容放在 NSVisualEffectView 里（`.popover` 材质，state `.active`），圆角 10，描边 0.5pt（黑 12% / 白 14%）。
- 圆角：控件和气泡 5；页签、图标按钮、分段 6；卡片、面板、设置窗口里的分组 10。
- 字号只用四档：
  - 15 用于「栏量」和百分比，半粗；
  - 13 用于卡片标题和设置行；
  - 12 用于正文、分段、气泡、订阅行；
  - 10 用于重置时间、更新时间、坐标轴、套餐徽章、「官方 / 仅本机」。
  - 所有数字都用等宽数字（monospacedDigit）。
- 文字颜色：主色 #1D1D1F / #F5F5F7；次要为黑 55% / 白 55%；三级为黑 35% / 白 30%。
- 叠色：悬停 黑 6% / 白 9%；选中页签 黑 7% / 白 11%；进度底轨 黑 6% / 白 8%；分隔线 黑 10% / 白 8%。
- 卡片：白 62% / 白 6%，0.5pt 描边（同分隔线色）。
- 强调色：橙 #F2780C → #FFA040 渐变。只用在这几处：套餐徽章底、柱子、开关打开、链接和「重试」。
- 健康色沿用 QuotaLevel：正常为系统绿，低于 20% 为系统红。
- 气泡：亮色是深底白字（#1E1E20 94%），暗色反过来是浅底黑字（#F5F5F7 96%）；圆角 5，内边距 5/8，阴影 0/2/8 20%。
- 进度条 5pt，页签额度条 4pt，都是圆头。

## 3. 顶栏三入口
- 高 44。左边是 20pt 圆角橙底图标，后面跟「栏量」15pt 半粗。右边从左到右依次是：「x 分钟前更新」10pt 三级色，然后三个 26×24 图标按钮，间距 2。
- 三个按钮用 SF Symbol（16pt）：`arrow.clockwise`、`arrow.down.circle`、`gearshape`。悬停时出叠色底、显示手型和气泡；按下时缩到 0.94。
- **刷新**：调用现有 `onRefresh`。刷新时图标匀速转圈（1 秒一圈），左边的文字换成「正在刷新…」；刷新中再点不起作用（沿用现有 guard）。
  - 刷新完显示「刚刚更新」，之后显示「x 分钟前更新」，满 60 分钟后显示「x 小时前更新」，文字每分钟更新一次。
  - 新增 `lastUpdated`，在 onAllDone 时写入。
  - 气泡两行：「刷新」/「上次更新 x 分钟前」。
- **升级**：Sparkle 自动检查发现新版本时，**只在图标右上角亮 7pt 红点，不自动弹窗**。实现上开启 Sparkle 的温和提醒：`SPUStandardUserDriverDelegate` 里 `supportsGentleScheduledUpdateReminders` 返回 true，定时检查找到更新时 `standardUserDriverShouldHandleShowingScheduledUpdate` 返回 false，由我们亮红点；用 `SPUUpdaterDelegate` 的找到更新 / 没找到更新回调更新 `availableUpdateVersion`。
  - 气泡：有新版本时为「有新版本 x.y.z」/「点击查看更新内容并安装」；没有时为「检查更新」/「当前 0.2.0，已是最新」。
  - 点击：先收起面板（hidePanel）并激活 App（NSApp.activate），再调用 `updater.checkForUpdates(nil)`。面板在 statusBar 层级，不先收起会挡住 Sparkle 窗口。
- **设置**：点击后先收起面板、激活 App，再打开设置窗口（见第 7 节）。

## 4. 服务页签（替换系统分段控件）
- 两个等宽卡片式页签，间距 4，高 44，圆角 6。
- 第一行：服务图标 14pt + 名称 12pt 半粗，靠右是剩余百分比 10pt。第二行：4pt 额度条。
- 百分比和额度条取周剩余；只有 5 小时窗口的服务取 5 小时剩余。颜色沿用 QuotaLevel。
- 选中的页签用选中叠色和主色文字；未选中的用次要色，悬停时出叠色。
- 没登录或没有额度时，百分比显示「—」，额度条为空轨。

## 6. 用量卡
- 标题行依次为：「Token 用量」13pt 半粗，「官方」（Codex）或「仅本机」（Gemini）10pt 三级色，最右边日/周/月分段。
- 日/周/月分段自己画：底是进度底轨色，选中项为白块（暗色白 14%）、12pt 半粗。
- 柱状图沿用现在的自绘实现，只换皮：
  - 柱顶 2pt 圆角，橙色渐变；
  - 网格只画中线（虚线，10%）和底线（18%）；
  - Y 轴三档刻度和刻度规则不变，刻度和日期标签 10pt。
- **悬停**：其余柱子降到 45% 不透明，悬停的柱子上加 0.5pt 竖线，上方显示两行气泡：日期（或区间）和「N Tokens」。气泡不超出图区。
- **加载**（「正在统计…」时机同 0.1.5）：图区放 14 根灰色占位柱，做脉冲动画（1.4 秒），下面写「正在统计…」。
- **失败**：显示 `icloud.slash` 图标、「官方用量暂时拿不到」12pt 三级色，下面一个「重试」按钮（橙色 12pt，悬停出叠色）。**「重试」只调用现有刷新**。
- Gemini 的「全部失败」「部分对话读取失败」「没有记录」这些文案和逻辑不变，「部分失败」仍然写在标题行。

## 7. 设置窗口
- 独立 NSWindow + NSHostingController，宽 340。标题「栏量设置」，有标准红黄绿按钮，不能缩放，只开一个：已经开着时再点就把它放到最前。
- App 是没有 Dock 图标的 accessory app，开窗口前要 NSApp.activate。不用 SwiftUI Settings scene。
- 只有两项，放在一个圆角 10 的分组里，每行高 44：
  1. 「登录时启动」，说明「开机后自动出现在菜单栏」。用现有 SMAppService 逻辑，和右键菜单里那项状态一致。
  2. 「自动检查更新」，说明「有新版本时在面板上提示」。绑定 `updater.automaticallyChecksForUpdates`，默认开。
  - 开关打开时为橙色，说明文字 10pt 三级色。
- 底部信息行（不算设置项）依次为：图标、「栏量 0.2.0」、有新版本时红色「x.y.z 可用」、「检查更新」链接（行为同第 3 节升级按钮），靠右「退出栏量」（悬停时红底 10%，调用现有 quitWithFallback）。
- 不加自动下载安装，也不加其他设置项。

## 8. 附带修复
1. README 第 10 行「参考说明」还写着读取 `~/.codex/sessions/**/*.jsonl`，0.1.5 已经删掉了这项扫描。改成只列 `~/.codex/auth.json`、Antigravity 的 OAuth token 文件与钥匙串项。README 不受 CI grep 约束，但描述要和实际一致。
2. 0.1.5 遗留：诊断开关 `--debug-gemini-scan-timing` 第二段「缓存重扫」，前提是第一段已经把结果写进临时缓存文件，但这个文件实际没写成。
   - 原因：临时缓存放在 `NSTemporaryDirectory()` 根目录。写缓存时会把所在目录改成 700；写入失败又被 `try?` 吞掉，所以第二段 opened 不为 0。
   - 改法：临时缓存放进独立子目录 `NSTemporaryDirectory()/lanliang-timing-<UUID>/gemini-usage-cache.json`。第一段扫描后检查这个文件存在，输出里加一项 `cacheWritten=yes/no`。结束时删掉整个子目录。
   - 只改诊断路径，不改正式缓存逻辑。
