# 栏量 LanLiang v0.1.4 契约（mind，2026-11-24 22:2x NY，范围以 PM 22:20 NY 为准）

一件事：Gemini 页签加「Token 用量」图，只用本机 Antigravity 对话数据，不算费用。其余同 0.1.3。

## 1. 数据源（只读，绝不写、不锁、不改 `~/.gemini` 下任何文件）
- 统计三个目录，存在才读：
  1. `~/.gemini/antigravity/conversations/`（桌面 App）
  2. `~/.gemini/antigravity-ide/conversations/`
  3. `~/.gemini/antigravity-cli/conversations/`
- 不读 `~/.gemini/antigravity-backup/`，不读 `conversation_summaries.db`（本版不要标题）。
- 只读 `*.db`（每个对话一个 SQLite）。`*.pb` 是更早的格式，跳过，不计入失败。
- 去重：对话 id = 文件名去掉扩展名。同一 id 出现在多个目录时只算一份，取 db/-wal 修改时间最新的那份。
- 读法：把 `<id>.db` 和存在的 `<id>.db-wal` 复制到 `NSTemporaryDirectory()` 下的私有临时目录，用系统自带 SQLite（`import SQLite3`）只读打开副本，读完删掉临时目录。`-shm` 不复制（SQLite 会从 WAL 重建）。复制前后文件大小或修改时间变了，就重来，最多 3 次，仍不一致算这次读取失败。单个对话 db+wal 超过 512MB 直接跳过并算失败。

## 2. 格式（Antigravity 自己的格式，没有公开文档，手写最小 protobuf 解码器，只认 varint / 64 位 / 长度前缀 / 32 位四种 wire type；不得复制任何参考项目代码）
- `steps(idx, step_type, metadata)`：`metadata` 是 protobuf。字段 1 = 本步时间（Timestamp：子字段 1 秒、2 纳秒），字段 9 = 本次模型调用的 token 用量消息。
- 用量消息子字段：2 输入，3 输出，4 缓存写入，5 缓存读取，9 思考输出，10 回复输出。字段 3 为 0 时，输出 = 9 + 10。
- 一个对话里只要有任何一步带字段 9，就只用 steps；一步都没有时，退回 `gen_metadata(idx, data)`：`data` 字段 1 是调用信息，其中字段 4 是同样结构的用量消息；时间取 `last_step_index + 1` 那一步的时间（键值对在调用信息字段 20 里，子字段 1 键、2 值）。
- 没有 token 计数的调用不计。某次调用没有时间，就按该对话 db/-wal 的最新修改时间计。
- 两张表都没有 → 不是对话库，算失败。坏的 protobuf 记录跳过这一条，不算整个对话失败。

## 3. 口径
- 每次调用 token = 输入 + 输出 + 缓存读取 + 缓存写入，按本地时区日历日（yyyy-MM-dd）累加。
- 包含 Antigravity 里调用 Claude 模型的部分，不按模型拆，不算费用。
- 时间范围跟图一致：每日 30 天、每周 12 周、每月 6 个月，读全部对话，不限条数。

## 5. 性能（老板 Mac 实测：antigravity/conversations 33 个 .db + 6 个 .pb，共约 187MB，最大约 22MB；antigravity-ide 4 个对话；没有 antigravity-cli）
- 唯一做法：内存缓存，键为 db 绝对路径，值为（db 大小、db 修改时间、wal 大小、wal 修改时间）+ 该对话的按日 token 字典。每次刷新只列目录、stat 文件；四个值全没变就用缓存，变了才复制重读。已经不在目录里的条目从缓存删掉。不写磁盘缓存。
- 扫描在后台串行队列执行，主线程只接收结果；同一时间最多一个扫描，刷新时扫描还在跑就不再新起。菜单栏和面板不得因扫描卡顿。
- 刷新时机和 Codex 本机扫描相同（随常规刷新和手动刷新）。
